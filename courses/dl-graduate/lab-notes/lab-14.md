# Lab Notes 14 — Capstone Topic Finalization and Literature Search

**Concept recap:** this lab is a structured planning session, not a coding exercise; its output
feeds directly into the capstone proposal.

**Common pitfalls:**
- Choosing a topic that is still too broad after Task A (e.g., "study Transformers" rather than
  a specific, falsifiable comparison) — push back explicitly if a topic could not be stated as a
  single concrete, testable question.
- Candidate papers (Task B) that are not real, citable, publicly locatable papers — a vague
  half-remembered reference is not sufficient; require an actual title/author/venue, even if the
  exact year is uncertain, consistent with this course's citation standard.
- Skipping Task C's rapid-critique pass and jumping straight to "this paper looks relevant" —
  without at least identifying each candidate's central claim, students often discover too late
  (in Week 15) that a "relevant" paper does not actually address their motivating question.
- Drafting a motivating question (Task D) that is actually a restatement of an existing paper's
  question rather than a genuine gap/extension/comparison — the capstone requires a reproduced or
  **extended** experiment, not a plain restatement.

**Debugging tip:** not applicable (no code this lab); the equivalent check is: can a classmate who
has not heard the topic before restate the motivating question after reading Task D's draft once?
If not, it needs another revision pass before the proposal is submitted.

**Instructor tip:** this lab's most common failure mode is a topic that is really an entire
subfield (e.g., "graph neural networks") rather than a scoped project — use the Week 15/16
example-topics lists (`course-contents.md`, `assignments/capstone-proposal-guidelines.md`) as a
calibration reference for appropriate scope.
