# Capstone Project — Grading Rubric

**Due:** Week 16 | **Weight:** 20% of course grade total (includes proposal, implementation, presentation)

| Component | Weight (of 20%) | Criteria |
|---|---|---|
| Proposal | 2% | Clear problem statement, feasible dataset, at least three planned algorithm families, sound evaluation plan |
| Implementation — correctness | 5% | Code runs; correctly implements and compares models from at least three algorithm families; handles data appropriately (no leakage) |
| Implementation — evaluation | 5% | Appropriate metrics chosen and computed; cross-validation or an equivalent honest evaluation procedure used; results reported honestly (including weaknesses) |
| Report — tradeoff discussion | 4% | Written discussion of tradeoffs across the compared models (e.g., accuracy vs. interpretability, training time, robustness to preprocessing choices) |
| Presentation | 4% | Clear 5–7 min talk; results shown with at least one chart/table; answers Q&A questions accurately |

## Grading Notes
- A project that honestly reports a technique that underperformed, with sound analysis of why,
  can score as well as a project with strong results but weak analysis — the evaluation,
  comparison, and understanding matter as much as raw performance.
- At least three distinct algorithm families from the course (e.g., a linear/regularized model, a
  tree-based/ensemble model, and an SVM or k-NN model) must be compared; projects comparing only
  variations of a single family (e.g., three different tree depths) do not meet this bar.
- Pairs must clearly attribute each member's contribution in the report; grading can differ
  between partners if contributions were significantly uneven.
