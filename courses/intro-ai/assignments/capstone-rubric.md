# Capstone Project — Grading Rubric

**Due:** Week 16 | **Weight:** 20% of course grade total (includes proposal, implementation, presentation)

| Component | Weight (of 20%) | Criteria |
|---|---|---|
| Proposal | 2% | Clear problem statement, a single well-scoped classical technique, sound evaluation plan |
| Implementation — correctness | 6% | Code runs; correctly implements the proposed classical technique (search, logic, planning, or probabilistic reasoning) |
| Implementation — evaluation | 5% | Evaluation plan from the proposal is actually carried out; results reported honestly, including failure cases |
| Report | 3% | Concise written report: problem, approach, results, 1+ limitation/next step |
| Presentation | 4% | Clear 5–7 min talk; demo or worked example shown; answers Q&A accurately |

## Grading Notes
- A project that honestly reports a technique that didn't fully work (e.g., a planner that
  times out on a larger instance, or a Bayesian network whose simplifying independence
  assumptions break down on a trickier query), with sound analysis of why, can score as well as
  a project that works smoothly but is analyzed shallowly.
- The capstone must be built on a classical technique from Weeks 3–11 (search, logic, planning,
  or probabilistic reasoning), per the proposal guidelines — a project built primarily around
  scikit-learn or another applied-ML workflow does not meet this course's capstone requirement,
  regardless of how well it performs.
- Pairs must clearly attribute each member's contribution in the report; grading can differ
  between partners if contributions were significantly uneven.
