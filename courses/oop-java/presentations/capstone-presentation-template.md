# Capstone Presentation Template (Student-Facing)

**Target length:** 5–7 minutes + Q&A | **Given to students in Week 11 alongside the proposal
guidelines, used for the Week 16 presentation.**

## Required Slides
1. **Title** — project name, your name(s).
2. **Problem statement** — what domain does your program model, and why does it fit a class
   hierarchy and/or interface-based design?
3. **Class hierarchy / interfaces** — your abstract base class and/or interface, and concrete
   classes implementing it (a UML sketch, Week 14 style, is encouraged), naming which methods are
   abstract/interface methods.
4. **Generics & Collections** — which generic type or Collections Framework container stores/
   processes your objects, and why.
5. **Error handling** — the realistic error condition(s) your program detects, and the
   exception(s) thrown and caught.
6. **Demo** — a live or recorded demonstration of the program working end-to-end, including at
   least one error condition being handled gracefully.
7. **Limitations & next steps** — one honest limitation and what you'd try with more time.
8. **Questions** — invite audience questions; be ready to point to the specific line(s) of your
   own code implementing inheritance/interfaces, generics/collections, and exception handling.

## Presentation Tips
- Practice the timing — 5–7 minutes goes faster than it sounds; cut detail, not clarity.
- Lead with the problem, not the code — the audience needs to care about the "why" before the
  "how."
- Show the program actually running early, including the error-handling path, not just the
  happy path — a working demo of both is worth more than a slide describing one.
- Be honest about what didn't work — the rubric (`assignments/capstone-rubric.md`) explicitly
  rewards sound, correct code over simply claiming every feature works, and specifically checks
  for correct `@Override` usage, a correct `equals`/`hashCode` pair where needed, and real
  exception handling, not just feature count.
