# Capstone Project — Proposal Guidelines

**Due:** Week 11 | **Weight:** 2% of the Capstone grade (20% total course weight)

## What to Submit
A 1-page proposal (`capstone_proposal.pdf` or `.md`) covering:
1. **Problem statement**: what will the console application manage or do (e.g., track grades,
   catalog books, manage inventory)?
2. **Data design**: which class(es) will represent each record, and which array(s) or
   `ArrayList`(s) will hold the collection of records?
3. **Core operations**: which methods will the program provide (e.g., add, remove, search,
   update, report/summarize)?
4. **Persistence plan**: how will the program's data be saved to and loaded from a file between
   runs (`Scanner`/`BufferedReader` and `PrintWriter`/`FileWriter`)?
5. **Team**: individual or pair, with each member's planned contribution if a pair.

## Approval
The instructor will respond within one week with approval or requested revisions. Projects must
use techniques covered in this course (arrays/`ArrayList`, simple classes, methods, file I/O, and
optionally recursion or sorting/searching) — novel/advanced techniques beyond the syllabus
(e.g., inheritance, GUIs, databases) require instructor pre-approval and are not required for
full credit.

## Example Topics (for inspiration, not a closed list)
A student grade-book manager, a simple library catalog, a personal inventory tracker, a to-do
list manager with save/load, a basic contact book, or a small expense tracker — each reading and
writing its data to a file so the program's state survives between runs.
